# 身分証検出・確認画面の改善（2026-10-23）

## 確認した問題と方針

- 利用者の申告は「統合前の確認画面でサムネイルが重なる」。各行に独立した固定寸法のプレビュー枠を設け、隣接行への描画を防ぐ。
- 解析時のサムネイルは元画像全体だった。検出成功時は出力と同じ中心・傾き・切り出し寸法によるプレビューをプロキシ上で作り、検出失敗時のみ元画像を表示する。A4出力ファイルは確認後に生成する。
- 公的寸法は出力寸法の照合にしか使われず、候補選択は色差・形状に依存していた。既存の色差閾値に加えて近傍補正用の低い閾値でも候補を探し、DPIと規格寸法（ID-1および旅券見開き）の許容差内の候補があれば優先する。種別の自動判定は行わない。
- 同一券面を閾値違いで複数候補と数えない。規格一致候補がない場合は従来の候補選択・規格外警告・実寸配置を維持する。DPI欠損時は既存仕様どおり300dpiを使う。
- 確認画面の収まり判定と配置枠表示は、出力処理と同じく `cardSizeMm` を参照する。旧処理は余白を含む `physicalSize` を再判定していたため、券面が大きすぎても配置枠のサイズで判定されていた。

## 検証

個人情報を含まない合成画像のみを使い、淡い券面と濃い印刷、規格外の余分な矩形、閾値間の重複、複数カード、確認画像と出力の対応を検証する。lint・型検査・全単体テスト・Windowsパッケージを実行し、結果はPRと報告に記載する。

- 回帰確認: 追加した淡い券面・余分な矩形の2ケースは、旧検出処理では失敗し、修正後は券面の中心と寸法まで一致した。
- 150/300/600dpi、左右25度の傾き、規格外サイズの従来処理、複数候補の警告を確認した。
- 確認用サムネイルと、実際のA4出力から取り出したタイルの平均画素差が5未満（0〜255の各チャンネル値）になることを検証した。
- Electron 38で合成サムネイル12枚を表示し、1180×820、900×600、表示倍率150%・200%の4条件、それぞれ先頭・スクロール後の計8条件で、画像間の矩形の交差がなく、画像が各セル内に収まることを計測した。900px幅と1180px幅の画面キャプチャも確認した。
- 最終確認: `npm run verify`（lint・型検査・12ファイル196テスト）と `npm run package`（Windows x64のポータブル版・NSISインストーラ）を通過。制限環境での配布資材取得はDNS解決に失敗したが、ネットワーク利用可能な実行で生成できた。

## 試用

`npm run package` で生成する `release/IdentificationIntegratorOnA4 0.1.1.exe` を実行する。
入力フォルダを再解析し、各行の検出結果、券面サイズ、警告を確認してから出力する。
元画像は変更しない。インストーラは `release/IdentificationIntegratorOnA4 Setup 0.1.1.exe`。

## 未確認・制約

- 利用者が問題を確認した実画像では未検証。旧版のサムネイル重なりそのものは手元で再現できていないため、原因を断定せず表示枠を明示した。確認画面の表示検証では合成データをIPCの代わりに渡している。
- 種別を変更してもサムネイルは解析時の検出結果を表示する。配置枠に収まるカードは出力の切り出し枠、枠超過の書類は検出四隅の範囲を表示する。
- 背景と外周の差が低い閾値にも届かない画像や、物理的に重なった券面の分離は保証しない。入力1ファイルにつき最良候補1枚を扱い、複数候補は従来どおり警告する。
- Windowsのパッケージ生成を確認するが、インストーラによるインストール操作は行わない。
